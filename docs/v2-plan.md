# codesys-mcp-toolkit v2 — Step 0 findings and rewrite plan

Status (2026-11-07): Phase 0 spike done, Phase 1 core done, Phase 2 simulation (text) done. Phases 3-4 (panel) not started.

## 1. Summary

v1 is replaced, not patched. v2 is an ESM TypeScript MCP server with a
persistent CODESYS bridge, an ST-only tool set, and a truST-backed simulation
layer with an MCP App panel on top. The CODESYS bridge copies proven designs
from other projects; the simulation panel is the part nobody else has.

## 2. What Step 0 found

### 2.1 This repo (v1)
- **Two diverged baselines.** GitHub `main` / npm 1.1.16 is the 1.1.3 code
  (all Python inlined in `server.ts`). Local `main` carries two unpushed
  "Refactored the code" commits (1.1.4: `src/scripts/*.py`, session files) —
  the refactor upstream reverted because POU creation broke. Claude Desktop on
  this machine runs the npm 1.1.16 build.
- **Every call cold-starts CODESYS** (`CODESYS.exe --runscript=tmp.py`).
  The "persistent session" mode is a stub: `executeScript` in
  `codesys_session.ts` still calls `executeCodesysScript`, and
  `start_session.py` uses f-strings, which IronPython 2.7 cannot parse.
- **Scripts are generated by string interpolation** and written as `latin1`
  with no coding header — non-ASCII text breaks (PR #9).
- **`compile_project` never reports errors** — it prints "compilation
  initiated" and exits (PR #10).
- **Reads are resources only** (`project-structure`, `pou-code`), which Claude
  Desktop doesn't expose to the model (issue #6).
- `@modelcontextprotocol/sdk` ^1.10.2, CommonJS, no tests, no CI tests.

### 2.3 Other CODESYS MCP projects
- **CODESYS SP22 Patch 1 ships its own MCP server** (separate license, 19
  tools, named-pipe plugin). This machine has SP21. Ignore for now; possible
  later backend.
- **zbest1000/mcptoolkit-for-codesys** (Python, MIT) — most robust bridge:
  persistent CODESYS running a watcher with preloaded op handlers, JSON
  `{op,args}` requests over a file queue, heartbeat file (idle/busy+deadline)
  with healthy/hung/dead detection and respawn, `system.prompt_handling` to
  suppress modals, `confirm:true` on online writes.
- **phobicdotno/Codesys-MCP-Master** (TS, MIT, 132 tools) — WinForms timer on
  the UI thread so the runscript returns and menus stay usable; routes to the
  CODESYS install matching the project's version; refuses SP conversion;
  already has `mirror_export` and PLCopen import/export.
- **luke-harriman/Codesys-MCP** — breaks on SP21+ because
  `execute_on_primary_thread` was removed.
- **None of them can switch off online tools** (login/download/write/force).

### 2.4 truST (trust-platform — your repo)
- Rust, MIT/Apache, v0.33.0 (2026-11-06), prebuilt Windows zip; native AOT
  needs a ~216 MB pinned toolchain bundle.
- **Simulation:** `trust-runtime play --simulation --time-scale 1..100`;
  sim time advances exactly one cycle per scan (never wall clock).
- **Debug:** `trust-debug` DAP over stdio — conditional/hit-count breakpoints,
  logpoints, step in/over/out, setVariable/force, pause. Needs a debug image.
- **Control endpoint:** NDJSON over `tcp://127.0.0.1` + per-start token —
  `status`, `var.force/unforce`, `io.*`, `pause/resume`, `cycle.step`,
  `config.set`. Also `trust-dev agent serve` (JSON-RPC stdio).
- **Plant models** live in `simulation.toml`: `gravity_tank`, `first_order`,
  `integrator`, … with noise, disturbances/faults, actuator limits; lockstep
  with scans. **Wired by `%I/%Q` address only.** `libraries/plant` is
  PLC-side equipment FBs, not process models.
- **CODESYS profile** (`vendor_profile = "codesys"`) is two weeks old. Parser
  has METHOD, PROPERTY GET/SET (nested inside the FB), INTERFACE, EXTENDS,
  IMPLEMENTS, THIS/SUPER, POINTER/REFERENCE, UNION, VAR_STAT, ACTION.
  **Missing:** VAR_INST, FB_init/FB_exit, `__ISVALIDREF`, `__QUERYINTERFACE`,
  `__TRY`; pragmas ignored except `qualified_only`; no Util/CAA/SysLib.
- **PLCopen import drops property GET/SET bodies** (replaced by stubs,
  `PLCO225`). → The mirror must compose ST text directly, not go through
  PLCopen.
- **Unsafe defaults:** web UI on `0.0.0.0:8080` and discovery are ON; with no
  `io.toml` it falls back to machine I/O. Simulation mode rejects physical
  drivers. v2 must write these configs explicitly.

### 2.5 MCP Apps
- Spec stable (2026-01-26). `@modelcontextprotocol/ext-apps` 2.0.4 needs SDK
  v2 split packages + zod 4; 1.7.5 needs SDK ≥1.29. **ESM only.**
- UI = `ui://` resource, `text/html;profile=mcp-app`, linked via
  `_meta.ui.resourceUri`; single-file HTML (Vite + singlefile); CSP via
  `_meta.ui.csp`, external origins blocked by default.
- App-only tools: `_meta.ui.visibility: ["app"]`.
- **No server→app push: poll** (official example: 2 s). Plan ~4 Hz with
  delta events, not 10 Hz.
- **Every tool call mounts a new panel and old ones keep running** → use the
  documented supersession pattern (seq + BroadcastChannel) so only the newest
  panel polls.
- `updateModelContext` overwrites; host may deliver it only with the next user
  message. Claude Desktop renders apps from local stdio servers.
- Gate UI registration on the host's `io.modelcontextprotocol/ui` capability;
  every tool returns useful text regardless.

## 3. Decisions

### 3.1 Scope
- **ST only.** Supported objects: Program, FB, Function, Method, Property
  (GET/SET), Action, Interface, DUT (struct/enum/union/alias), GVL. Non-ST
  objects (SFC, CFC, LD, FBD, IL) are detected and reported, never edited;
  the simulator refuses to run code that calls them unless stubbed explicitly.
- **No online tools.** v2 never logs in, downloads, writes or forces on a
  controller. Enforced by having no such ops in the watcher at all, so the
  simulation rule holds by construction.
- **SP22 built-in MCP server:** not used.

### 3.2 CODESYS bridge (copying zbest + Master)
- One persistent CODESYS per server, started with `--runscript=watcher.py`
  (scripts staged to a local folder; UNC paths silently fail).
- Watcher = preloaded op handlers; requests are JSON `{id, op, args}` files,
  written tmp+rename; results likewise. **No generated Python** — removes
  injection and input-encoding bugs.
- UI-thread WinForms timer (Master) so the IDE stays usable; `system.delay()`
  loop for `--noUI`.
- Heartbeat file with current op + deadline; host classifies
  healthy/hung/dead, kills and respawns; adopts a live watcher on restart.
- `system.prompt_handling` set at startup; watcher exits when the server's PID
  dies.
- UTF-8 everywhere: `codecs.open(..., 'utf-8-sig')`, decode fallbacks
  utf-8 → mbcs → latin-1, `ensure_ascii=False`, ASCII-only watcher source.
- Version routing: detect CODESYS installs, refuse to open a project in a
  different SP (avoids silent conversion).
- `health` / `diagnose` answer without waiting on the watcher.

### 3.3 Stack
- ESM, TypeScript, Node ≥20, MCP SDK v2 split packages + ext-apps 2 + zod 4.
- vitest; a mock watcher (Python 3) for tests without CODESYS; live tests
  gated by an env var; GitHub Actions on windows-latest.
- Panel: Vite + vite-plugin-singlefile, CodeMirror 6, plain SVG for P&ID,
  small canvas trend.

### 3.4 truST integration
- Pin one truST version; check it at startup.
- **Mirror composes ST text directly** (FB file with nested METHOD/PROPERTY/
  ACTION blocks), one file per top-level object, plus generated
  `runtime.toml` (web/discovery off, debug image), `io.toml`
  (`driver = "simulated"`), `simulation.toml`, and `Configuration.st`.
- **Symbolic plant wiring:** `plant.toml` maps plant signals to ST variable
  names; v2 generates `%I/%Q` addresses + `VAR_CONFIG`/`AT` mapping and the
  matching `simulation.toml`. (Alternative: add symbolic wiring to truST.)
- Control: runtime control endpoint for run/pause/step/force/read/time-scale;
  `trust-debug` (DAP, stdio) for breakpoints and stepping.
- Since you own truST, gaps can be fixed there instead of worked around:
  properties in PLCopen import, VAR_INST, FB_init, symbolic plant wiring,
  explicit "plant frozen while halted" guarantee.

## 7. Phase 0 spike results (2026-11-07)

Verdict: **go.** truST can simulate CODESYS ST once the gaps in
[`spike/trust-fidelity/TRUST-GAPS.md`](../spike/trust-fidelity/TRUST-GAPS.md)
are fixed in truST. The spike ran the full path (CODESYS SP21 → export →
composed mirror → truST build → closed loop with the `gravity_tank` plant →
breakpoint, step, force, interlock trip) with three source workarounds:
`E.X` → `E#X`, `VAR_INST` → `VAR`, and `__ISVALIDREF` removed.

What changes in the plan:
- **Use the runtime control endpoint for everything, not DAP.** It already has
  breakpoints, step in/over/out, pause/resume, eval, force, and stack/variable
  reads. DAP is needed only until truST exposes expression compilation for
  conditional breakpoints (gap B1).
- **The plant freezes at a breakpoint.** Verified: the level was unchanged for
  3 s of wall time while paused. No extra work needed.
- **The mirror approach holds.** Composing ST text directly (not PLCopen)
  keeps property bodies. The rules the mirror needs are listed in
  TRUST-GAPS §C.
- **CODESYS bridge facts for v2:**
  - Cold start ~138 s, warm ~17 s. That confirms the persistent bridge.
  - Stdout only reaches the caller when CODESYS isn't started with redirection.
  - Object names are localised ("Taskkonfiguration"), so identify objects by
    type GUID.
  - SP21 has `system.prompt_handling` but not the newer
    `script_prompt_handling`, so probe for both.
  - `build()` only compiles POUs a task reaches.
  - Read messages right after `build()`, because any later build
    (`check_all_pool_objects`) wipes them.
  - Errors carry object + parent + `position_text` ("Line 1, Column 1 (Impl)").
  - `create_interface()` adds `EXTENDS __System.IQueryInterface`.
  - Task items in `task.pous` are plain strings.
- **truST `build` needs its toolchain** (~181 MB, auto-installed). v2's
  `sim_start` must check `toolchain status` first and ask.
- **Rebuild takes ~35 s** for the tank project, so experiments that only change
  parameters should use `force` / `config.set`, not rebuilds.

Spike files: `spike/trust-fidelity/` (CODESYS script `cds_spike.py`,
`compose_mirror.py`, `trust-template/`, `repros/` + `run_repro.py`).

## 8. Phase 2 results (2026-11-07)

Done: the acceptance demo steps 1-2, 4-5 and 7-8 run as text, through the MCP
tools, against real CODESYS SP21 and truST 0.33 (`test/live/sim.live.test.ts`).
The same flow runs against truST alone with a faked CODESYS export
(`test/sim-trust.test.ts`, skipped when truST isn't installed).

Code: `src/sim/` (mirror, plant, runtime, control client, controller, tools).

Decisions made while building it:
- **The control endpoint only, no DAP.** Breakpoints, stepping, the stack,
  locals, forcing and the time scale all work over NDJSON on 127.0.0.1 with a
  per-start token.
- **Paused between calls.** `run_scans` is exact: a hit-count breakpoint sits
  on the scan counter of a generated harness program that runs first in the
  fastest task.
- **CODESYS paths in truST.** Program instances get their POU's own name, so
  `PRG_Tank.nTrips` works in both. Breakpoints and build errors use CODESYS
  object lines through the mirror's line map.
- **Symbolic plant wiring.** `plant.toml` wires plants by variable name, and
  the mirror generates the AT addresses. Plant-fed variables are forced
  through `io.force` (TRUST-GAPS B17).
- **Enum literals.** The mirror rewrites `E.X` to `E#X`. CODESYS SP21 rejects
  `E#X` and truST rejects `E.X` (A1), so there is no common form.
- **Conditions in the toolkit** until truST compiles condition text (B1, B19).
- **Experiments restart the process.** truST's control restart doesn't reset
  plants (B13) and it can't start paused (B14). A fresh start always completes
  one scan before handing over.
- **Safety.** `src/sim/` reads CODESYS only through `export` and `tasks.list`,
  and the controller module has no access to the bridge. A test checks this.
  Before every start the toolkit checks for simulated I/O, simulation enabled,
  web, discovery and mesh off, and a loopback control endpoint, and truST
  always runs with `--simulation`.

New truST gaps: B11-B19 in TRUST-GAPS.md.
